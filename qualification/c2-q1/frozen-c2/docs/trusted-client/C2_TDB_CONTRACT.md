# C2 R4 native Trusted Decision Boundary

Status: source candidate, not frozen, not production admitted.
Baseline: lioensky/VCPChat main 7ef7fdd21bce84f1605013e15d2367c07c336716.

Electron Main owns TrustedClientNativeService and the only canonical pending request. The service adapts frozen S2-B/A1/A2 delivery semantics in approvalDelivery.js; no Vue or renderer owns protocol authority. The display, request identity, argsDigest and decision frame all derive from the same frozen Host request record. The client never recomputes an authority digest.

The dedicated BrowserWindow loads bundled approval.html, approval.js and approval.css with context isolation, sandbox requested, web security, Node disabled, DevTools disabled, a separate session partition, denied permissions/navigation/new windows/webviews and an exact local-resource allowlist. All authority text uses textContent. Technical fields provide readable text, deterministic UTF-8 byte escaping and uppercase spaced hex; no normalization or truncation. Invalid, ill-formed or >8192-byte technical values disable Allow while bound Deny remains possible. No generic notification fallback exists.

The trusted-approval preload exposes only onPresentAuthority(handler) and submitDecision({viewGeneration,decision}). It forwards no Electron event objects. Extra fields fail closed. Main independently checks exact webContents, current mainFrame, null parent, bundled URL, visible/focused window, window/request/socket/view generations, eligibility epoch, canonical pending ownership and native provenance evidence. Ordinary Chat preload is unchanged and has no signer, trusted socket or generic trusted-send interface.

Eligibility is ELIGIBLE/INELIGIBLE/UNKNOWN, separate from Host admission. Lock, suspend, hide, blur, destruction, navigation, terminal/snapshot/ACK, connection replacement, expiry and integrity failure invalidate the view. A 100ms conservative UX check disables expired or unavailable presentations; submission independently rechecks the deadline synchronously. Resume/unlock does not revive a view. Fresh sync plus fresh presentation and explicit action are required. Missing lock evidence fails closed.

HumanInputProvenance consumes a short-lived, single-use native evidence handle bound to requestId, ALLOW/DENY, trusted view generation, request generation, socket generation and eligibility epoch. OS_ISOLATED and USER_PRESENCE_VERIFIED require an independently admitted native attestor. event.isTrusted, window focus, unlock and recent authentication never substitute. No such platform attestor is admitted in this candidate. Tests inject isolated fixture attestations only.

R4 decision path: PRESENTED → HUMAN_DECIDED → DECISION_BOUND → FRAME_PREPARED → FIRST_SEND_ATTEMPTED → SENDING → Host ACK/terminal or DELIVERY_UNKNOWN. After asynchronous provenance collection, Main rechecks the complete context, prepares the exact v1 tool_approval_response and immediately rechecks again before the first socket.send. There is no await, queue or timer between that final check and send invocation. The frame contains requestId, approved, protocolVersion=1 and the unchanged argsDigest. No signature is added to a decision. Frames are memory-only, single-attempt, never persisted or replayed.

A send call does not prove Host acceptance. ACK wait and sync wait are each 10 seconds. An ambiguous request/generation cannot send another decision. Recovery uses fresh authenticated connection generation and successful Host sync; ACTIVE requires a new human click, terminal disables action, absent requests become STALE_UNKNOWN. Only the current sole attempt's ACCEPTED ACK establishes accepted decision identity. Conflicting subsequent Host terminal/snapshot is recorded as protocol inconsistency without replacing Host truth. Old connection ACK/snapshot/lifecycle callbacks cannot alter the new generation. Local expiry is not Host terminal truth.

Sensitive classifier is shared by ordinary filter, notification and Main transport guard. CodexWorker grant/revoke are excluded before every ordinary auto rule. main.html loads this tiny classifier synchronously before the existing filter; a missing classifier fails closed. Generic notifications show information only. Main permits generic approval responses only for observed non-sensitive request IDs; it never elevates generic VCPLog. Unrelated ordinary auto approval remains supported.

C1 wire reuse: exact /human-client/v1/vcp-chat route family and /VCPlog/vcp-chat-approval, capability in the existing header, exact Host challenge bytes, five existing purposes only: enrollment-claim, capability-mint, channel-upgrade, self-revoke, session-authenticate. Channel readiness requires a proof already sent on the current socket. The Host remains authoritative for current admission and receipt lifecycle. TEST_ONLY Host fixtures never become production human connections.

Enrollment, admission, authenticated session and local identity recovery are separate projections. Descriptor is a non-secret provider-adjacent locator. Key only → RECOVERY_REQUIRED; descriptor only → KEY_LOST; mismatched pair → IDENTITY_RECOVERY_LOCKED; both absent → UNENROLLED; exact pair → recover same enrollment and authenticate a fresh session. Reconnect never silently creates a key or enrolls. Native provider code targets Windows CNG P-256 and macOS Secure Enclave P-256; Linux has no production provider. Direct native create/sign/descriptor mutations are hard-disabled until separately reviewed caller-isolation admission exists. No environment switch enables them.

Security epoch helper models withdrawal → old identity closure → verified C1 continuity → awaiting separate Host admission. It never admits a new epoch itself. Path A is UNPROVEN/unavailable. Path B tests use isolated authority evidence; real production migration is not performed. No second revocation/receipt/approval registry is introduced.
