# C2 source security declaration

The source profile and frozen Host VCPChat profile remain PRODUCTION_DISABLED. This candidate creates no production identity, enrollment, session, approval, receipt or grant. It is not deployment or platform admission evidence.

If an Agent can inject arbitrary code into Electron Main, replace the trusted packaged artifact, control native signer execution, obtain equivalent OS signing privileges, or exercise admitted Human-input capabilities, this client cannot claim Human Authorization provenance without another independently reviewed OS boundary preventing those capabilities. Same user, executable path, PID, TPM presence, focus, event.isTrusted and biometric recency do not establish that boundary.

Windows CNG and macOS Security.framework provider source is present but uncompiled and untested on those operating systems. Key non-extraction and invocation isolation are UNKNOWN/UNPROVEN. All native create/sign/persist operations fail with PROVIDER_NOT_ADMITTED, including direct addon callers. The actual native platform operations cannot be activated by renderer/settings/environment/profile claims. A later reviewed implementation/evidence gate is necessary before they can be used. No broker or generic localhost signing service exists. The software signing adapters used by tests are not production providers and are never loaded by product bootstrap.

Linux compiles and loads the rejecting N-API addon. No production key provider, lock-state attestor or HumanInputProvenance attestor is implemented for Linux. The isolated Electron component test required --no-sandbox because this environment's SUID helper was not configured; it proves packaged resource loading/context bridge behavior only, not OS sandbox enforcement or Human-input isolation. The product BrowserWindow still requests sandbox=true. No system/SUID configuration was changed.

The packaged Linux artifact has RunAsNode, NODE_OPTIONS and inspect-related fuses disabled and OnlyLoadAppFromAsar enabled. Embedded ASAR integrity enforcement is not established on Linux. Platform signing, installation ACL assurance, native invocation isolation, input provenance and rollback-resistant provider access are UNPROVEN. Supplementary manifest hashes detect changed bytes but are not a root of trust. Development/unsigned artifacts remain ineligible.

Windows descriptor code uses a persisted key property; macOS uses a provider-adjacent Keychain entry. Neither path's durability, ownership or access policy has runtime evidence in this Linux task. Recovery tests use isolated native-provider substitutes. Same-epoch continuity is a logical contract, not a claim of tested macOS Team ID/entitlement continuity. A lost key cannot be recovered from VCP_Key, UserAuth, deviceName, ordinary AppData or a descriptor alone.

The five frozen cryptographic authentication purposes consume unchanged Host signingInput bytes. P-256 signs SHA-256(M), outputs strict low-S IEEE-P1363 via provider conversion; Ed25519 is preserved. Actual frozen Host fixtures independently verified both algorithm paths. Human ALLOW/DENY is not separately signed under R4; it is bound by Main and submitted over the existing authenticated dedicated channel. Revocation affects future participation, not frozen receipt history.

Source tests and mocked adversarial proofs do not establish OS-level caller isolation, real user presence, a real enrollment, cross-platform runtime support or production admission. No automatic replay or automatic production enablement exists. Historical C1/A1/A2 failures and the previous C2 contract STOP remain immutable.

These inform implementation contracts; they are not runtime evidence for this build.
